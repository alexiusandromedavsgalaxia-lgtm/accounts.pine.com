Política de privacidad

La política completa sobre la información que gestiona Pine Accounts, autenticación, sesiones, sincronización, Developer Account, seguridad, infraestructura y solicitudes.

1. Finalidad de esta política

Esta Política de privacidad describe las categorías de información que Pine Accounts gestiona para proporcionar identidad, autenticación, sesiones, funciones de cuenta, Developer Account y sincronización de Account Data. No describe como existentes sistemas que todavía no hayan sido implementados.

2. Datos de identidad

DatoUso
IDIdentificar de forma estable la cuenta.
NombreMostrar y administrar la identidad.
CorreoIdentificar la cuenta durante el acceso.
Hash y salComprobar contraseñas sin guardar su texto original.
Fecha de creaciónGestionar el ciclo de vida.

3. Contraseñas

La contraseña recibida durante el registro no se guarda como texto plano. La implementación actual utiliza PBKDF2 con SHA-256, una sal individual y 100.000 iteraciones. Durante el acceso se vuelve a derivar el valor y se compara con el almacenado.

La finalidad de este proceso es permitir la verificación sin conservar la contraseña original.

4. Sesiones y cookies

Después de un acceso correcto se crea un token aleatorio de sesión. La base de datos guarda una representación derivada del token, el propietario y la expiración. El navegador recibe la cookie pine_session.

La cookie utiliza HttpOnly, Secure y SameSite=Lax. La duración implementada actualmente es de 30 días. Logout elimina la sesión correspondiente y expira la cookie.

5. Account Data

Account Data contiene registros con ID, usuario, clave, valor y fechas de creación y actualización. La clave se encuentra dentro del espacio de datos del usuario. Los objetos JSON se serializan para poder conservar estructuras.

6. Sincronización

Los dispositivos que inician sesión en la misma cuenta pueden consultar los registros pertenecientes a esa cuenta. El servidor determina la propiedad mediante la sesión autenticada, no confiando en un ID arbitrario enviado por el navegador.

La sincronización de Account Data no implica sincronización automática de todos los archivos del dispositivo.

7. Developer Account

Si se crea un Developer Account, pueden almacenarse nombre, correo, empresa, web, descripción, plan, estado, API key y timestamps. El registro se relaciona con la cuenta mediante user_id.

Las API keys son credenciales sensibles y deben mantenerse privadas.

8. Preferencias locales

La preferencia de apariencia utiliza localStorage con la clave pine-theme. Este valor es una preferencia de interfaz y no constituye una credencial de acceso.

9. Seguridad y acceso

Los endpoints protegidos resuelven primero la sesión y después consultan datos vinculados al usuario autenticado. Las bases D1 se exponen al código servidor mediante bindings y no directamente al navegador.

Las respuestas del endpoint de datos utilizan Cache-Control: no-store para reducir el riesgo de almacenamiento accidental de respuestas privadas en cachés.

10. Infraestructura

La arquitectura actual utiliza Cloudflare Pages para el sitio y sus Functions, y D1 para las bases configuradas. Estos proveedores pueden procesar información técnica necesaria para prestar la infraestructura.

11. Conservación

Los datos se conservan mientras resulten necesarios para las funciones correspondientes, de acuerdo con las capacidades de gestión de la plataforma y las obligaciones aplicables. Las tablas utilizan timestamps para registrar creación y actualización donde corresponde.

12. Eliminación y solicitudes

Las solicitudes relativas a los datos de una cuenta deben dirigirse a los canales oficiales. Puede ser necesario verificar que quien solicita una acción controla la cuenta afectada.

13. Seguridad de terceros

No deben introducirse contraseñas, tokens o API keys de otras personas en Account Data sin una finalidad legítima. Pine no convierte automáticamente cualquier dato introducido por un usuario en información pública.

14. Cambios de la política

La política puede modificarse cuando cambien los datos tratados, las funciones o los requisitos legales. La fecha de revisión identifica la versión publicada.

15. Contacto

Para cuestiones de privacidad utiliza los canales oficiales disponibles. Para detalles técnicos sobre autenticación, datos y APIs consulta la documentación técnica.

16. Categorías de información

La información gestionada puede dividirse en identidad, autenticación, sesiones, datos de desarrollador, datos genéricos de cuenta y preferencias locales. Cada categoría tiene una finalidad distinta y no debe confundirse con las demás.

17. Qué no contiene el modelo de cuenta

La tabla de usuarios no almacena la contraseña original. Las respuestas públicas de la API de cuenta tampoco devuelven el hash ni la sal. El navegador no recibe directamente las credenciales internas de D1.

Account Data tampoco significa que todos los archivos, fotos, documentos o elementos del dispositivo se suban automáticamente. Solo se sincronizan los registros que una función de almacenamiento envía al servicio.

18. Datos introducidos voluntariamente

Cuando el usuario crea un Developer Account puede introducir empresa, sitio web y descripción. Cuando utiliza Account Data puede elegir claves y valores. El usuario debe evitar introducir secretos de terceros o información que no tenga derecho a almacenar.

19. Finalidades separadas

La identidad sirve para administrar la cuenta. La autenticación sirve para comprobar acceso. Developer Account sirve para funciones de desarrollador. Account Data sirve para sincronización. La preferencia pine-theme sirve para la interfaz local. Estas finalidades no deben interpretarse como una autorización general para reutilizar cualquier dato para cualquier propósito.

20. Sesiones entre dispositivos

Al iniciar sesión en otro dispositivo se crea o utiliza una sesión asociada a la misma cuenta. El servidor identifica al usuario a partir de la sesión autenticada. El hecho de que dos dispositivos compartan una cuenta no significa que uno pueda leer datos pertenecientes a otra cuenta.

21. Seguridad de las bases

Las bases D1 están conectadas al código servidor mediante bindings. No se exponen como una interfaz SQL pública del navegador. Las consultas protegidas utilizan la identidad resuelta por la sesión para limitar el conjunto de datos.

22. Minimización

Las respuestas de cada superficie intentan devolver los campos necesarios para esa función. Por ejemplo, la consulta pública de cuenta devuelve identidad básica, mientras que el flujo de autenticación utiliza internamente información adicional que no se presenta como parte del perfil.

23. Registro técnico y diagnóstico

Los mecanismos de infraestructura pueden generar información técnica necesaria para operar, proteger y diagnosticar el servicio. Los secretos de autenticación no deben incorporarse voluntariamente a registros de diagnóstico.

24. Retención de sesiones

Las sesiones tienen una expiración almacenada. Una sesión expirada deja de satisfacer la consulta de autenticación aunque su fila pueda requerir una tarea posterior de limpieza. La expiración lógica y la limpieza física son conceptos distintos.

25. Eliminación y ciclo de vida

Las solicitudes de eliminación o gestión de datos deben dirigirse por los canales oficiales. La eliminación de una sesión no debe interpretarse como eliminación automática de la cuenta o de todos sus datos asociados.

26. Cambios materiales

Si cambia de forma material la información tratada o la finalidad de una función, la política puede actualizarse para reflejar ese cambio. La versión y fecha publicadas permiten distinguir revisiones.

27. Seguridad de credenciales

Las contraseñas, cookies de sesión y API keys son categorías sensibles. No deben incluirse en capturas públicas, repositorios, ejemplos reales o campos de Account Data cuando no sea necesario.

28. Privacidad y documentación técnica

La documentación explica cómo funcionan los componentes técnicos; esta política explica qué información se relaciona con ellos. Ambas páginas deben leerse conjuntamente para comprender el servicio sin confundir implementación con finalidad de tratamiento.
