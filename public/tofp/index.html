1. Finalidad de esta política

Esta Política de privacidad describe las categorías de información que Pine Accounts gestiona para proporcionar identidad, autenticación, sesiones, funciones de cuenta, Developer Account y sincronización de Account Data. No describe como existentes sistemas que todavía no hayan sido implementados.

2. Datos de identidad

DatoUso
IDIdentificar de forma estable la cuenta.
NombreMostrar y administrar la identidad.
CorreoIdentificar la cuenta durante el acceso.
Hash y salComprobar contraseñas sin guardar su texto original.
Fecha de creaciónGestionar el ciclo de vida.

3. Contraseñas

La contraseña recibida durante el registro no se guarda como texto plano. La implementación actual utiliza PBKDF2 con SHA-256, una sal individual y 100.000 iteraciones. Durante el acceso se vuelve a derivar el valor y se compara con el almacenado.

La finalidad de este proceso es permitir la verificación sin conservar la contraseña original.

4. Sesiones y cookies

Después de un acceso correcto se crea un token aleatorio de sesión. La base de datos guarda una representación derivada del token, el propietario y la expiración. El navegador recibe la cookie pine_session.

La cookie utiliza HttpOnly, Secure y SameSite=Lax. La duración implementada actualmente es de 30 días. Logout elimina la sesión correspondiente y expira la cookie.

5. Account Data

Account Data contiene registros con ID, usuario, clave, valor y fechas de creación y actualización. La clave se encuentra dentro del espacio de datos del usuario. Los objetos JSON se serializan para poder conservar estructuras.

6. Sincronización

Los dispositivos que inician sesión en la misma cuenta pueden consultar los registros pertenecientes a esa cuenta. El servidor determina la propiedad mediante la sesión autenticada, no confiando en un ID arbitrario enviado por el navegador.

La sincronización de Account Data no implica sincronización automática de todos los archivos del dispositivo.

7. Developer Account

Si se crea un Developer Account, pueden almacenarse nombre, correo, empresa, web, descripción, plan, estado, API key y timestamps. El registro se relaciona con la cuenta mediante user_id.

Las API keys son credenciales sensibles y deben mantenerse privadas.

8. Preferencias locales

La preferencia de apariencia utiliza localStorage con la clave pine-theme. Este valor es una preferencia de interfaz y no constituye una credencial de acceso.

9. Seguridad y acceso

Los endpoints protegidos resuelven primero la sesión y después consultan datos vinculados al usuario autenticado. Las bases D1 se exponen al código servidor mediante bindings y no directamente al navegador.

Las respuestas del endpoint de datos utilizan Cache-Control: no-store para reducir el riesgo de almacenamiento accidental de respuestas privadas en cachés.

10. Infraestructura

La arquitectura actual utiliza Cloudflare Pages para el sitio y sus Functions, y D1 para las bases configuradas. Estos proveedores pueden procesar información técnica necesaria para prestar la infraestructura.

11. Conservación

Los datos se conservan mientras resulten necesarios para las funciones correspondientes, de acuerdo con las capacidades de gestión de la plataforma y las obligaciones aplicables. Las tablas utilizan timestamps para registrar creación y actualización donde corresponde.

12. Eliminación y solicitudes

Las solicitudes relativas a los datos de una cuenta deben dirigirse a los canales oficiales. Puede ser necesario verificar que quien solicita una acción controla la cuenta afectada.

13. Seguridad de terceros

No deben introducirse contraseñas, tokens o API keys de otras personas en Account Data sin una finalidad legítima. Pine no convierte automáticamente cualquier dato introducido por un usuario en información pública.

14. Cambios de la política

La política puede modificarse cuando cambien los datos tratados, las funciones o los requisitos legales. La fecha de revisión identifica la versión publicada.

15. Contacto

Para cuestiones de privacidad utiliza los canales oficiales disponibles. Para detalles técnicos sobre autenticación, datos y APIs consulta la documentación técnica.
