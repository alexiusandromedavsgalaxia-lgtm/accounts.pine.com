Términos y condiciones

Las reglas completas de utilización de Pine Accounts, desde el registro y las credenciales hasta Developer Account, Account Data, usos permitidos, disponibilidad y cambios.

1. Objeto y alcance

Estos Términos y condiciones regulan el uso de Pine Accounts, la creación de cuentas, el acceso a la interfaz web, las funciones de identidad, Account Data y las funciones de Developer Account. El documento define las reglas de utilización del servicio y debe leerse junto con la documentación técnica y la política de privacidad.

2. Definiciones

Pine Account es la identidad principal. Developer Account es el registro de desarrollador asociado a una Pine Account. Account Data son los datos asociados a una cuenta mediante las funciones de almacenamiento. Sesión es la autorización temporal de un navegador. Credencial incluye contraseñas, tokens y API keys.

3. Registro y cuenta

Para crear una cuenta se proporciona nombre, correo y contraseña. El correo debe ser válido y único. La información de la cuenta debe mantenerse razonablemente actualizada. No debes crear una identidad destinada a suplantar deliberadamente a otra persona.

Una misma cuenta puede tener sesiones en varios dispositivos. Una sesión y la cuenta son conceptos distintos: cerrar una sesión no significa borrar la cuenta.

4. Credenciales y seguridad

Las contraseñas se procesan mediante derivación criptográfica y no se almacenan como texto plano. Las sesiones utilizan tokens aleatorios y una cookie protegida. Debes mantener privadas tus credenciales y cerrar sesiones que ya no reconozcas.

Regla práctica: nunca publiques una contraseña, token de sesión o API key real en repositorios, capturas, foros o documentación.

5. Usos prohibidos

  • Intentar acceder a cuentas ajenas.
  • Manipular o falsificar sesiones.
  • Evitar controles de autorización.
  • Intentar ejecutar SQL arbitrario mediante una API.
  • Interferir deliberadamente con la disponibilidad de Pine.
  • Utilizar credenciales obtenidas sin autorización.
  • Abusar de límites o recursos de la infraestructura.

6. Developer Account

Developer Account proporciona un espacio para información de desarrollador como empresa, web, descripción, plan, estado y credenciales. Su registro está vinculado de forma única a la cuenta propietaria.

Una API key debe tratarse como secreto. No debe incrustarse en aplicaciones cliente si su función exige confidencialidad. La interfaz puede mostrarla administrativamente, pero eso no elimina su carácter de credencial.

7. Account Data

Account Data permite guardar valores bajo claves pertenecientes a una cuenta. La combinación de usuario y clave es única y una escritura repetida sobre la misma clave actualiza el registro. Es apropiado para preferencias y estados pequeños, no para convertir el servicio en almacenamiento ilimitado de archivos.

8. Contenido y propiedad

La información que introduzcas debe ser tuya o debes disponer de autorización suficiente para almacenarla. Guardar contenido en Pine no significa que Pine pueda publicarlo libremente.

La interfaz, documentación, marcas y software de Pine son elementos del servicio y no deben presentarse como propios fuera de las licencias aplicables.

9. Disponibilidad

La plataforma puede depender de navegadores, redes e infraestructura externa. Puede existir mantenimiento, cambios de interfaz, errores o interrupciones. Las funciones experimentales pueden cambiar sin conservar exactamente el mismo comportamiento.

10. Cambios de funciones y API

Los endpoints documentados constituyen el contrato técnico de una función. No debes construir una integración crítica sobre detalles internos que no estén documentados. Cuando una API cambie, la documentación debe actualizarse para reflejar su comportamiento vigente.

11. Suspensión y terminación

Una sesión puede finalizar por logout, expiración o medidas de seguridad. El acceso a determinadas funciones puede limitarse cuando sea necesario para proteger usuarios, infraestructura o cumplir obligaciones legales.

La terminación de una sesión no implica automáticamente la eliminación de todos los datos de la cuenta.

12. Responsabilidades

Debes proteger tus credenciales, revisar las integraciones que conectes a Pine y evitar compartir secretos. También debes respetar los límites técnicos y no intentar convertir una API de cuenta en una interfaz administrativa de base de datos.

13. Limitaciones

Pine es una plataforma en evolución. En la medida permitida por la legislación aplicable, no se garantiza que cada función esté disponible permanentemente ni que una interfaz permanezca idéntica. Nada aquí pretende excluir derechos que legalmente no puedan excluirse.

14. Cambios de estos términos

Estos términos pueden actualizarse cuando cambien las funciones, la arquitectura o los requisitos legales. La fecha y versión de esta página identifican el documento vigente.

15. Contacto

Las consultas sobre estas condiciones deben dirigirse a los canales oficiales disponibles en Pine. Para preguntas sobre endpoints, tablas y ejemplos técnicos, consulta la documentación.

16. Reglas de integración

Las aplicaciones que utilicen las APIs de Pine deben tratar los endpoints como interfaces autenticadas y respetar los códigos HTTP. Una integración no debe asumir que una respuesta positiva significa que todos los campos futuros permanecerán idénticos.

Buenas prácticas

  • Usar HTTPS en producción.
  • No registrar cookies de sesión en logs.
  • No incrustar API keys privadas en aplicaciones públicas.
  • Usar las rutas documentadas en lugar de consultar directamente D1.
  • Gestionar respuestas 401, 400, 405 y 409 de forma explícita.

17. Cuenta en varios dispositivos

Una Pine Account puede tener sesiones independientes en distintos dispositivos. Cerrar una sesión concreta no equivale necesariamente a cerrar las demás. El usuario debe revisar los dispositivos desde los que mantiene acceso cuando una credencial pueda haberse expuesto.

18. Developer Account y credenciales

La creación de un Developer Account no concede acceso administrativo a la base de datos ni convierte automáticamente todos los endpoints internos en APIs públicas. Las credenciales de desarrollador deben utilizarse únicamente en las funciones para las que hayan sido emitidas.

Queda prohibido intentar obtener, adivinar, reutilizar o extraer credenciales pertenecientes a otras cuentas.

19. Account Data y almacenamiento

Account Data está pensado para información de cuenta de tamaño razonable, como preferencias, estados y configuraciones. No debe utilizarse para almacenar contenido que provoque una carga desproporcionada o que requiera garantías de almacenamiento que la plataforma no documente.

20. Cambios de infraestructura

Pine puede modificar componentes de infraestructura, proveedores, nombres internos de bindings o estructura de implementación siempre que mantenga las obligaciones aplicables y, cuando corresponda, actualice la documentación pública.

21. Seguridad y abuso

Los intentos de acceso no autorizado, manipulación de sesiones, explotación de vulnerabilidades, extracción de datos de terceros o interferencia deliberada con el servicio pueden provocar medidas de protección, limitación o suspensión.

La comunicación responsable de vulnerabilidades debe evitar publicar secretos, datos personales o instrucciones que faciliten ataques antes de que exista una solución.

22. Cambios de documentación

La documentación técnica puede evolucionar con el código. Cuando exista una diferencia entre una descripción antigua y el comportamiento actual publicado, debe utilizarse la referencia vigente del servicio, sin perjuicio de las obligaciones contractuales aplicables.

23. Servicios de terceros

Pine puede depender de infraestructura externa para hosting, base de datos, DNS, entrega de contenido u otras funciones. La disponibilidad de esos proveedores puede afectar al servicio sin que una página concreta de Pine pueda garantizar su continuidad independiente.

24. Comunicaciones de seguridad

Cuando una situación de seguridad afecte de forma relevante a una cuenta o función, Pine puede aplicar medidas destinadas a proteger la cuenta, como invalidar sesiones o limitar temporalmente determinadas operaciones.

25. Interpretación

Estos términos describen el funcionamiento y las reglas del servicio, pero no sustituyen las normas imperativas que resulten aplicables. Si una disposición no puede aplicarse legalmente en un caso concreto, las restantes disposiciones no quedan automáticamente anuladas.
